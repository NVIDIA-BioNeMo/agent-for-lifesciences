# arize-phoenix 13.0.3 declares arize-phoenix-evals>=2.8.0 with no upper bound, but
# its phoenix/experiments/functions.py still imports phoenix.evals.models.rate_limiters,
# which was REMOVED in arize-phoenix-evals 3.0. Without this cap the resolver pulls
# evals 3.x and `from phoenix.otel import register` (and `phoenix serve`) crash with
# `ModuleNotFoundError: No module named 'phoenix.evals.models'`, silently disabling
# all training telemetry. Cap to the 2.x line that still ships phoenix.evals.models.
arize-phoenix-evals>=2.8.0,<3
# arize-phoenix 13.0.3 pins strawberry-graphql 0.287.3, which accepts graphql-core <3.4
# but imports graphql.execution.ExecutionContext -- REMOVED in graphql-core 3.3.0.
# arize-phoenix-client registers an auto-loaded pytest plugin that imports phoenix,
# so without this cap pytest itself dies at startup with an ImportError, and
# `from phoenix.otel import register` fails, silently disabling telemetry.
# Drop this cap when arize-phoenix is upgraded to a release with a newer strawberry.
graphql-core>=3.2.0,<3.3
